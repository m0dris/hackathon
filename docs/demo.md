# Проверка основного сценария

Нужны работающий бот, HTTPS webhook, контейнеры и два аккаунта MAX. Логина и пароля внутри бота нет: пользователь определяется по событиям MAX. Ссылка на бот пока отсутствует. Это инструкция, а не отчёт о проверке в MAX.

Входные значения: `fixtures/demo.json`. При повторной проверке на той же БД не создавайте повторно профиль, дом или связь с квартирой. Создайте новую заявку. ID заявки заранее неизвестен, фиксируйте полученный номер.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | A открывает бота, выбирает «Я управляющая компания» | Запрос имени и фамилии |
| 2 | Вводит `Тест Оператор`, затем `+70000000001` | Главное меню с «Мои дома» |
| 3 | «Мои дома», «Добавить дом», вводит `Тестовый город`, `Учебная`, `1` | Подтверждение добавления дома |
| 4 | B открывает бота, выбирает «Я житель» | Запрос имени и фамилии |
| 5 | Вводит `Тест Житель`, затем `+70000000002` | Главное меню с «Мои квартиры» |
| 6 | «Мои квартиры», «Добавить квартиру», тот же адрес и квартира `12` | Подтверждение найденного дома и квартиры |
| 7 | «Заявки», «Новая заявка», категория «Грязный подъезд» | Запрос заголовка |
| 8 | Заголовок и описание из fixture | «Заявка #… создана», статус «Новая» |
| 9 | A: «Заявки», фильтр «Новые» | Заявка с адресом, описанием и контактом |
| 10 | A: «Взять в работу» для полученного номера | Статус «В работе» |
| 11 | B повторно открывает «Заявки» | Тот же номер, «В работе» |
| 12 | A: фильтр «В работе», «Завершить» | Статус «Выполнена» |
| 13 | B повторно открывает «Заявки» | Тот же номер, «Выполнена» |

## Ошибки и ограничения

| Проверка | Ожидаемое поведение |
| --- | --- |
| Заявка без квартиры | Предложение сначала добавить квартиру |
| Неизвестный адрес | Сообщение «Такой дом не найден», повторный запрос города |
| Текст вместо номера квартиры | Повторный запрос числа |
| Заголовок вне диапазона 3–255 символов | Ошибка и повторный запрос |
| Описание вне диапазона 3–2000 символов | Ошибка валидации, можно повторить ввод |
| Webhook без `X-Max-Bot-Api-Secret` | HTTP 401, диалог не вызывается |
| gRPC с чужой квартирой или чужой УК | `PERMISSION_DENIED` |
| Возврат выполненной заявки в работу | `FAILED_PRECONDITION` |

Пройдите сценарий в мобильной и веб-версии MAX. Сохраните дату, ссылку, commit hash и результаты. При перезапуске Go черновики диалогов теряются. Для возврата к меню используйте `/menu`.

Если бот не отвечает: проверьте `docker compose ps`, логи API и бота, HTTPS webhook и передачу секретного заголовка. Сообщение `subscribe MAX webhook failed` требует исправления конфигурации. `GET /healthz` проверяет только HTTP-процесс. Не прикладывайте рабочие токены к публичным логам.
